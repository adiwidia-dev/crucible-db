# Crucible DB v0.2.6

Released on 17 September 2026.

Crucible DB v0.2.6 introduces an explicit, audited SQL-policy review workflow for blocked Deployment Batch drafts. It keeps policy governance deliberate while making it practical for developers and administrators to resolve structurally reviewable SQL together.

## Explicit SQL-policy review

- Developers can choose **Request SQL policy review** when preflight is blocked only by structurally reviewable SQL that current workspace policy does not recognize.
- The handoff atomically saves the Deployment Batch as a non-executable draft, associates its current SQL-policy candidates, records an audit event, and notifies administrators.
- Administrators see requested candidates on the Overview dashboard, in the SQL Policy navigation badge, and in their notification inbox. They can allow an exact statement, allow a parser-proven reusable shape, deny the exact statement, or dismiss an observation.
- Requesters receive resolution notifications and decision notes. The request detail keeps the pending, allowed, or denied policy-review state visible.

## Safety and workflow guarantees

- SQL-policy decisions do not approve, schedule, dispatch, or execute a Deployment Batch. After an allow decision, the requester reviews the preserved draft and submits it through the ordinary approval workflow.
- Permanently prohibited SQL, missing targets, permission failures, and other hard blockers cannot enter the policy-review queue.
- The Deployment Batch editor now previews the server's current policy for the exact SQL and target. This lets an administrator decision immediately inform create and edit flows without relying on stale browser policy data or creating policy-candidate side effects.
- Review details include the current request revision, restoring review submission while retaining optimistic-concurrency checks and visible validation feedback.

## Upgrade from v0.2.5

This release includes a forward-only control-plane migration that records policy-review requests and administrator decision notes. The standard application startup applies it automatically.

Back up persistent storage and Redis, then update the application and native-proxy images together:

```dotenv
CRUCIBLE_IMAGE=hephaestus/crucible-db:0.2.6
CRUCIBLE_NATIVE_IMAGE=hephaestus/crucible-db-native:0.2.6
NATIVE_PROXY_EXPECTED_VERSION=0.2.6
```

Pull and recreate the stack. Verify `/health`, the native-proxy status indicator, a normal request review, and a blocked Deployment Batch draft that requests and receives an SQL-policy decision. See the [production deployment and upgrade guide](../operations/production.md) for backup, readiness, and recovery steps.
