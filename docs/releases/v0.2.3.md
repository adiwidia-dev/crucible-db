# Crucible DB v0.2.3

Released on 16 September 2026.

Crucible DB v0.2.3 is a backward-compatible operational reliability release. It keeps Native client readiness visible and accurate on the dashboard, aligns the development scheduler with the native proxy, and closes release-documentation drift.

## Highlights

### Persistent native-proxy readiness

- Keep the native-proxy status visible before the first scheduler report and after a stale cache entry expires instead of presenting the feature as disabled.
- Retain a health snapshot long enough to bridge the scheduler's minute-level refresh interval.
- Configure the development scheduler with the private native-proxy readiness endpoint, matching the application service.

### Compact operational status

- Move native-proxy readiness into a header icon immediately before the **CLI** link, where it remains visible without extending the dashboard below the viewport.
- Expose readiness, reported version, active instance count, active connection count, and last-check time through mouse hover and keyboard focus.
- Keep the dashboard summary connection count linked to the status indicator.

### Release consistency

- Verify in CI and release preflight that the README badge exactly matches the package version and release tag.
- Synchronize the README, changelog, MkDocs release metadata, and versioned release notes.

## Upgrade from v0.2.2

This release does not change the control-plane schema or require a configuration migration. Use the normal backup procedure, update both image variables to the same immutable tag, pull the images, and recreate the stack.

```dotenv
CRUCIBLE_IMAGE=hephaestus/crucible-db:0.2.3
CRUCIBLE_NATIVE_IMAGE=hephaestus/crucible-db-native:0.2.3
NATIVE_PROXY_EXPECTED_VERSION=0.2.3
```

If Native client access is enabled, confirm that the app, scheduler, and native proxy share the documented native-proxy environment settings. Then verify the header status indicator reports the expected version and a recent check time.

Use the [production deployment and upgrade guide](../operations/production.md) for complete backup, deployment, readiness, and rollback steps.
