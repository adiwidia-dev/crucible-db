# Crucible DB v0.4.3

Released on 23 October 2026.

Crucible DB v0.4.3 makes request handoffs easier to verify by showing each stable Query Request ID everywhere reviewers and operators find or discuss governed work.

## Faster request lookup

- The Query Requests table shows a dedicated `#ID` link for every visible request, and each detail page repeats the identifier beneath its title.
- Request search accepts a numeric ID, a `#`-prefixed ID, or a copied Query Request URL in addition to the existing title, requester, and connection search.
- Reviewers can match a reminder or shared link to the exact request without relying on similar request titles.

## Consistent notification context

- Recent notification menus and the full notification history show the stable request ID for request-related events.
- Operational email subjects and bodies include the same request ID while retaining the direct request link.
- Notifications unrelated to a Query Request remain unchanged and do not show an empty identifier.

## Upgrade from v0.4.2

Back up persistent storage, update the application and native-proxy images together, allow the application startup migration to finish, then reload Octane, Horizon, and scheduler workers:

```dotenv
CRUCIBLE_IMAGE=hephaestus/crucible-db:0.4.3
CRUCIBLE_NATIVE_IMAGE=hephaestus/crucible-db-native:0.4.3
NATIVE_PROXY_EXPECTED_VERSION=0.4.3
```

No configuration or database migration changes are required specifically for this request-identification release.
