# Crucible DB v0.2.9

Released on 22 September 2026.

Crucible DB v0.2.9 makes Overview a focused operational inbox instead of a growing collection of independent cards. It also gives table and registry surfaces complete boundaries on phones, keeping dense administrative and request data visually contained at every viewport size.

## Focused operational Overview

- Replace six independent counters with three summary groups: **Attention**, **Upcoming**, and **Live access**.
- Combine pending request reviews, SQL policy reviews, failed executions, scheduled executions, and active Query Access sessions into one prioritized operational queue.
- Tag every queue item by workflow type and retain query or access-level context, target, actor, error detail, timestamp, and policy-review request count where relevant.
- Add **All**, **Attention**, **Scheduled**, and **Live** filters with authorization-aware counts, and route each row directly to its request, SQL policy candidate, or active session.
- Limit the landing-page queue to the ten highest-priority visible items while preserving the complete history in the dedicated workflow pages.

## Responsive data surfaces

- Keep the three summary groups and operational queue separated with consistent spacing and complete card borders on narrow screens.
- Give shared data registries full borders and rounded corners at phone widths, covering People, Access Roles, Connection Groups, Audit Log, and authentication providers.
- Apply the same responsive boundary treatment to Query Requests, Connections, connection access policies, role policy tables, connection-group membership, active request sessions, execution history, and the role policy editor.

## Rolling deployment compatibility

- Accept an absent operational queue during frontend hydration so newly built assets remain usable while an older Octane worker is still serving the previous Overview payload.
- Continue polling the normalized summary, queue, and native-proxy status after workers are reloaded.

## Upgrade from v0.2.8

No database migration or configuration change is required. Back up persistent storage and Redis, then update the application and native-proxy images together:

```dotenv
CRUCIBLE_IMAGE=hephaestus/crucible-db:0.2.9
CRUCIBLE_NATIVE_IMAGE=hephaestus/crucible-db-native:0.2.9
NATIVE_PROXY_EXPECTED_VERSION=0.2.9
```

Pull and recreate the stack, then reload Octane workers. Verify `/health`, the Overview summary and each operational-queue filter, a request and connection table at phone width, and the native-proxy indicator. See the [production deployment and upgrade guide](../operations/production.md) for backup, readiness, and recovery steps.
