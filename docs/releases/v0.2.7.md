# Crucible DB v0.2.7

Released on 18 September 2026.

Crucible DB v0.2.7 strengthens deployment reliability and gives administrators a clear, read-only view of core operational health. It also makes the native CLI's standard help and version entry points easier to use and document.

## Large Deployment Batches

- Deployment Batch statements now support up to 1,000,000 characters. This accommodates large, governed data changes and spatial-data batches without truncating the control-plane record.
- The control-plane SQL columns use a migration-safe large-text representation for SQLite, PostgreSQL, and MySQL.
- The editor shows the current character count, keeps ordered statements separate, and presents validation feedback beside the affected statement action.

## Administrator System Status

- Administrators can open **Manage → Administration → Application → System Status** for cached, scheduler-refreshed health snapshots.
- The page reports the application runtime, control database, Redis, Horizon, scheduler heartbeat, native-proxy readiness, and generated Wayfinder route contract.
- It never runs infrastructure probes from a browser request and never exposes credentials, connection strings, SQL, or result data. Use it to identify the affected component, then follow the linked operational guidance.

## CLI and operations improvements

- `crucible --help` and `crucible connect --help` document the available commands and connection options directly from the CLI.
- `crucible --version` now prints only the installed release version, matching `crucible version` and making shell verification dependable.
- The operator documentation now describes the system-status scheduler heartbeat and cached checks alongside Horizon and the scheduler lifecycle.
- Setup-flow tests explicitly override Docker's inherited deployment token in PHPUnit's environment and server variables. This corrects a local test-environment mismatch without changing production setup authorization.

## Upgrade from v0.2.6

This release includes a forward-only control-plane migration that expands stored Deployment Batch SQL. Back up persistent storage and Redis, then update the application and native-proxy images together:

```dotenv
CRUCIBLE_IMAGE=hephaestus/crucible-db:0.2.7
CRUCIBLE_NATIVE_IMAGE=hephaestus/crucible-db-native:0.2.7
NATIVE_PROXY_EXPECTED_VERSION=0.2.7
```

Pull and recreate the stack. Verify `/health`, System Status, a normal Deployment Batch, the CLI version, and native-proxy readiness. See the [production deployment and upgrade guide](../operations/production.md) for backup, readiness, and recovery steps.

## Release artifacts and verification

The `v0.2.7` tag publishes multi-architecture application and native-proxy images, signed CLI archives and packages, checksums, SBOMs, build provenance, and a Homebrew cask update. Publication begins only after the application, application-database, native race, protocol integration, image smoke, artifact-verification, and documentation gates pass.
