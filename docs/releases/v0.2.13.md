# Crucible DB v0.2.13

Released on 30 September 2026.

Crucible DB v0.2.13 makes live database work easier to inspect and operate: browser Query Access can retain and page through complete captured results, SSO-only users can confirm their first passkey registration, and the Operational queue now leads with the latest work.

## Query Access results

- Browser Query Access retains an encrypted temporary snapshot for successful results while the session is active.
- Results page in 100-row pages and CSV exports include the full captured result, rather than only the first sample rows.
- Capture remains bounded to 5,000 rows or 25 MiB. A result that reaches either boundary is explicitly marked as truncated, and snapshots are removed when the session ends, is cancelled, or expires.

## Faster governed workflows

- The dashboard combines failures, reviews, policy work, ready batches, scheduled work, and live sessions in a latest-activity-first queue.
- Failed Deployment Batches can be resolved with an auditable note or linked replacement, removing resolved work from the live queue without deleting history.
- Deployment Batch editors support **Add below** and focused direct reordering, making longer ordered batches practical to edit.

## SSO and account confirmation

- A linked SSO provider can confirm protected account actions, including first-passkey registration for an SSO-only user.
- Two-factor recovery-code retrieval and passkey-registration confirmation flows now return clear protected-confirmation behavior.

## Upgrade from v0.2.12

This release adds a control-database migration for temporary Query Access result snapshots. Back up persistent storage and Redis, update both images, run migrations, then reload Octane workers:

```dotenv
CRUCIBLE_IMAGE=hephaestus/crucible-db:0.2.13
CRUCIBLE_NATIVE_IMAGE=hephaestus/crucible-db-native:0.2.13
NATIVE_PROXY_EXPECTED_VERSION=0.2.13
```

Verify a browser Query Access result can page beyond 100 rows, an SSO-only account can confirm first-passkey registration through its linked provider, and the dashboard puts the latest queue activity first.
