# Crucible DB v0.2.2

Released on 12 September 2026.

Crucible DB v0.2.2 is a backward-compatible maintenance release that hardens production image assembly and makes the supported Homebrew installation path discoverable.

## Highlights

### Production image hygiene

- Exclude ignored developer-local artifacts, generated documentation output, browser state, scanner configuration, and native build output from the Docker build context.
- Prevent stale local binaries and tools from being copied into the production application image.
- Reduce the locally verified application image size without removing a runtime feature.

### Release pipeline reliability

- Keep native test-image SBOMs as workflow artifacts rather than attempting to attach them from the read-only native test gate.
- Preserve least-privilege GitHub Actions permissions while publishing the application image, native-proxy image, signed CLI artifacts, provenance, and Homebrew cask.

### CLI installation

The supported Homebrew installation path is:

```bash
brew install --cask adiwidia-dev/tap/crucible
crucible version
```

GitHub Releases remain available for platform archives, Linux packages, checksums, Sigstore verification material, and SBOMs.

## Upgrade from v0.2.1

This release does not change the control-plane schema, environment-variable contract, or native-proxy protocol. Follow the normal production backup procedure, pin both images to the matching immutable release tag, pull them, and recreate the stack.

```dotenv
CRUCIBLE_IMAGE=hephaestus/crucible-db:0.2.2
CRUCIBLE_NATIVE_IMAGE=hephaestus/crucible-db-native:0.2.2
```

Use the [production deployment and upgrade guide](../operations/production.md) for backup, readiness verification, and rollback steps.

## Release artifacts and verification

The `v0.2.2` tag publishes multi-architecture application and native-proxy images, signed CLI archives and packages, checksums, SBOMs, build provenance, and the Homebrew cask update. The release gate reruns application tests, the application-database matrix, native race tests, protocol integration tests, image smoke tests, and artifact verification before publication.
