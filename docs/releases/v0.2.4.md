# Crucible DB v0.2.4

Released on 17 September 2026.

Crucible DB v0.2.4 is a backward-compatible reliability and maintenance release. It keeps audit attribution accurate when Deployment Batches leave the browser and run through queued or scheduled workers, aligns Application Settings form sections, and refreshes the supported frontend build toolchain.

## Highlights

### Accurate audit attribution for asynchronous deployments

- Capture the verified client IP at the trusted proxy boundary when a Deployment Batch is created, edited, dispatched, retried, or saved as a draft.
- Preserve that verified IP for queued execution, scheduled dispatch, preflight blocking, statement execution, completion, failure, and cancellation acknowledgement audit events.
- Keep console-only system work unattributed rather than incorrectly recording a worker loopback address.

### Consistent Application Settings layout

- Align Workspace identity with the full-width SMTP delivery and Factory reset sections.
- Retain the existing two-step Factory reset protection: the dialog requires the exact `RESET CRUCIBLE` confirmation phrase before its destructive action is enabled.

### Updated build toolchain

- Build the development and production frontend stages with Node.js 22.
- Refresh JavaScript tooling and the native PostgreSQL client dependency while retaining the verified application and native-proxy behavior.

## Upgrade from v0.2.3

This release includes a forward-only control-plane migration that stores the initiating client IP for Deployment Batch execution audits. The application entrypoint applies it automatically during the normal restart. No environment-variable or native-proxy protocol changes are required.

Back up persistent storage and Redis, then update both production images and the expected proxy version to the matching release:

```dotenv
CRUCIBLE_IMAGE=hephaestus/crucible-db:0.2.4
CRUCIBLE_NATIVE_IMAGE=hephaestus/crucible-db-native:0.2.4
NATIVE_PROXY_EXPECTED_VERSION=0.2.4
```

Pull and recreate the stack, then verify `/health`, the Native proxy status indicator, and a newly dispatched Deployment Batch audit event. Use the [production deployment and upgrade guide](../operations/production.md) for backup, deployment, readiness, and rollback steps.
