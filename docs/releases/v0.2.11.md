# Crucible DB v0.2.11

Released on 28 September 2026.

Crucible DB v0.2.11 adds an auditable SQL Policy review path for a narrow PostgreSQL update-trigger form without weakening the permanent procedural-SQL boundary.

## Exact PostgreSQL trigger review

- A PostgreSQL `CREATE TRIGGER … BEFORE UPDATE … FOR EACH ROW EXECUTE FUNCTION function_name()` statement can now be collected during Deployment Batch preflight as a SQL Policy candidate.
- Administrators may allow only the exact submitted statement; Crucible does not offer a reusable trigger shape.
- The candidate remains blocked until an administrator approves it through SQL Policy, then follows the normal Deployment Batch permission, approval, audit, and execution workflow.

## Safety boundary preserved

- The exception is PostgreSQL-only and accepts unquoted trigger, table, and function identifiers with a no-argument trigger function.
- Emergency SQL fallback, Query Access, and Native client execution do not permit this trigger form.
- Other trigger forms, function creation, and procedural SQL remain permanently blocked.

## Upgrade from v0.2.10

No database migration is required. Back up persistent storage and Redis, then update the application and native-proxy images together:

```dotenv
CRUCIBLE_IMAGE=hephaestus/crucible-db:0.2.11
CRUCIBLE_NATIVE_IMAGE=hephaestus/crucible-db-native:0.2.11
NATIVE_PROXY_EXPECTED_VERSION=0.2.11
```

Pull and recreate the stack, then reload Octane workers. Verify that the PostgreSQL trigger statement appears as an exact-only SQL Policy candidate and remains blocked until approved.
