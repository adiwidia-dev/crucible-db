# Crucible DB v0.2.14

Released on 2 October 2026.

Crucible DB v0.2.14 makes multi-connection work explicit everywhere it is reviewed or operated, expands failed-batch follow-up to the full visible replacement set, and ensures current account and approval policy still govern work at execution and session start.

## Multi-connection clarity

- Query Request lists, request details, notifications, and the Operational queue derive their connection summary from the complete Deployment Batch or Query Access target set.
- Compact previews show representative connections and disclose the remaining count, while the full target list stays available without making ordinary table rows or request headers excessively tall.
- Query Access creation displays approval and duration guidance for the selected browser or Native client workflow instead of reusing another workflow's policy fields.

## Current-policy enforcement

- Editing a request preserves no-approval behavior only when the requester's current effective policy still permits it; otherwise the request returns to **Pending Review**.
- Dispatch, retry, Query Access session start, and queued execution re-evaluate the original requester's active account, complete target scope, access level, approval requirements, and applicable duration.
- Queued Deployment Batch workers claim execution atomically and preserve cancellation if cancellation races with preflight or completion.

## Failure follow-up and feedback

- Failed Deployment Batch resolution can search every visible, newer, non-failed Deployment Batch by ID, title, status, or connection, including a replacement that already completed.
- The replacement menu remains contained within the resolution dialog and summarizes large target sets compactly.
- Execution feedback distinguishes queued work, successful completion, and failure with informational blue, success green, and error red notifications alongside their text and icons.

## Upgrade from v0.2.13

This release has no new control-database migration. Back up persistent storage and Redis, update the application and native-proxy images together, then reload Octane workers:

```dotenv
CRUCIBLE_IMAGE=hephaestus/crucible-db:0.2.14
CRUCIBLE_NATIVE_IMAGE=hephaestus/crucible-db-native:0.2.14
NATIVE_PROXY_EXPECTED_VERSION=0.2.14
```

Verify a multi-connection request shows its complete target scope, a completed newer Deployment Batch can be linked as a failure replacement, and a policy change before dispatch or session start returns newly reviewable work to **Pending Review**.
