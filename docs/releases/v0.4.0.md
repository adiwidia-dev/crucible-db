# Crucible DB v0.4.0

Released on 20 October 2026.

Crucible DB v0.4.0 makes browser Query Access execution responsive and bounded: statements run outside the web request, are limited at the target database, and can be cancelled by the authorized session user without ending the session.

## Responsive, cancellable browser queries

- Browser Query Access statements are queued on dedicated Redis workers, so a slow target query no longer occupies an Octane request worker.
- Execution history reports queued, running, cancellation-requested, succeeded, failed, cancelled, and timed-out states while the result panel refreshes automatically.
- The session user can cancel a queued or running browser statement from the result panel or execution history. Cancellation reaches the target database when execution has begun and does not end the session.
- Reconciliation closes abandoned queue or execution state after the bounded runtime, so history cannot remain indefinitely marked as running after a transport failure.

## Enforced runtime limits

- Administrators set the active maximum browser-query runtime at **Manage → Administration → Access & identity → Access Workflows**.
- PostgreSQL and MySQL receive the limit at the database session, while Redis and Horizon enforce a compatible worker boundary.
- `QUERY_ACCESS_MAX_TIMEOUT_SECONDS` is the deployment hard ceiling. Administrators can lower the active limit but cannot raise it above that ceiling.

## Dependency refresh

- Refresh React/Vite, Radix UI, ESLint, Prometheus, Redis, and immutable GitHub Actions dependencies.
- Native module dependencies now require Go 1.26; the production native image remains built with Go 1.27.2.

## Upgrade from v0.3.0

This release adds browser-query execution control fields and a dedicated Redis queue connection. Back up persistent storage and Redis, update the application and native-proxy images together, allow the application startup migration to finish, then reload Octane, Horizon, and scheduler workers:

```dotenv
CRUCIBLE_IMAGE=hephaestus/crucible-db:0.4.0
CRUCIBLE_NATIVE_IMAGE=hephaestus/crucible-db-native:0.4.0
NATIVE_PROXY_EXPECTED_VERSION=0.4.0
```

Keep `QUERY_ACCESS_MAX_TIMEOUT_SECONDS` at or below the target-database policy your operators intend to allow. After deployment, verify a browser query enters the queued state, completes or times out within the configured limit, and can be cancelled without ending its Query Access session.

## Release artifacts and verification

The `v0.4.0` tag publishes multi-architecture application and native-proxy images, signed CLI archives and packages, checksums, SBOMs, build provenance, and a Homebrew cask update after the application, database, native, artifact, and documentation gates pass.
