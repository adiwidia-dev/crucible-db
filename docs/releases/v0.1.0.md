# Crucible DB v0.1.0

Released on 24 August 2026.

Crucible DB v0.1.0 is the first stable open-source release of the governed database operations control plane. It provides reviewed Deployment Batches, time-bounded Query Access, connection-scoped role policy, SQL safety controls, notifications, and an auditable production-ready single-node Compose deployment.

## Highlights

### Governed deployment work

- Submit ordered batches of single SQL statements, each targeting an explicitly selected PostgreSQL or MySQL connection.
- Save incomplete or preflight-blocked work as a non-executable draft.
- Run per-statement preflight during preparation and again immediately before execution.
- Require independent approval according to effective policy across every selected target.
- Run immediately or at a requested schedule; late approval requires an explicit dispatch instead of running unexpectedly.
- Stop execution at the first failed statement and preserve completed and failed outcomes.
- Cancel eligible work and create linked retries with fresh policy and approval evaluation.

### Time-bounded Query Access

- Request read-only or explicitly authorized read + write browser sessions.
- Scope a session to one or more approved connections and enforce its declared level on every query.
- Browse the active connection schema, format SQL, run one statement at a time, and use `Cmd+Enter` or `Ctrl+Enter`.
- Select one statement from a larger editor buffer and use **Run selected**.
- Review result status, duration, row count, truncation, query history, and CSV exports.
- End sessions early or let the scheduler expire the approved access window.

### Access policy and review

- Apply reusable role policies through explicit connection groups.
- Add individual connection policies as deliberate exceptions that override the same role's group policy.
- Order multiple user roles so the first applicable policy controls overlapping access.
- Configure deployment access, Query Access capability, reviewer authority, read approval, write approval, and maximum write-session duration independently.
- Keep deployment write authority separate from interactive Query Access write capability; read-only is the default.

### SQL safety

- Govern read, `INSERT`, `UPDATE`, `DELETE`, `CREATE TABLE`, `ALTER TABLE`, `DROP TABLE`, and `TRUNCATE TABLE` statement families.
- Correctly classify `WITH … SELECT`, `INSERT`, `UPDATE`, and `DELETE` by their top-level executable statement.
- Warn on unbounded `SELECT`, `UPDATE`, and `DELETE` patterns while blocking definite policy, target, SQL, and schedule failures.
- Optionally enable an audited Emergency SQL fallback for one otherwise unsupported Deployment Batch statement.
- Continue blocking administrative, file-access, security-management, procedural, transaction-control, multi-statement, and `EXPLAIN ANALYZE` SQL.

### Identity and accountability

- Invitation-only accounts with password login, password reset, passkeys, two-factor authentication, recovery codes, and optional Google, GitHub, or Microsoft SSO.
- In-app and optional email notifications for reviews, execution, sessions, retries, cancellation, and connection failures.
- Request and connection watching, notification history, and operational recipient policy.
- Filterable and exportable audit history without stored credentials or SQL result rows in notification payloads.

## Installation

Download `compose.production.yaml` and `.env.production.example` from this release, prepare a private `.env.production`, and start the immutable image:

```bash
cp .env.production.example .env.production
docker compose -f compose.production.yaml pull
docker compose -f compose.production.yaml up -d
docker compose -f compose.production.yaml ps
curl --fail http://localhost:8000/health
```

The release image is:

```text
hephaestus/crucible-db:0.1.0
```

`hephaestus/crucible-db:alpha` points to the same release for compatibility with existing alpha deployments.

Read the complete [production deployment guide](../operations/production.md) before exposing the service.

## Upgrade and backup

This is the first tagged release. Existing alpha installations can upgrade after backing up both persistent application storage and Redis:

Before recreating the stack, compare the existing environment with `.env.production.example`. Set `SESSION_SECURE_COOKIE=true` when the public `APP_URL` uses HTTPS, and preserve the original `APP_KEY`.

```bash
docker compose -f compose.production.yaml pull
docker compose -f compose.production.yaml up -d --remove-orphans
docker compose -f compose.production.yaml ps
docker compose -f compose.production.yaml logs --tail=100 app redis
curl --fail http://localhost:8000/health
```

The production entrypoint runs forward-only migrations before Octane, Horizon, and the scheduler start. Changing `APP_KEY` makes encrypted credentials and settings unreadable.

## Security and verification

- Server-side authorization and validation cover database administration, role policy, requests, reviews, sessions, exports, notifications, and audit access.
- Target credentials and provider secrets are encrypted and omitted from serialized output.
- The production environment template enables HTTPS-only session cookies, and Compose reports application health through the Redis-aware `/health` endpoint.
- Composer and npm production dependency audits pass with no known advisories at release time.
- Full PHPUnit, PHPStan, Pint, ESLint, Prettier, TypeScript, MkDocs, production image, migration, health, and process smoke checks are part of the release gate.
- GitHub private vulnerability reporting is enabled; follow the repository [security policy](https://github.com/adiwidia-dev/crucible-db/security/policy) for responsible disclosure.

## Known constraints

- The supplied production topology is single-node because application metadata is stored in a local SQLite volume.
- Redis is required for queues, Horizon metadata, cache, and sessions.
- Query Access is available inside Crucible DB only; external database clients do not connect through a Crucible protocol proxy.
- A Deployment Batch is sequential but not atomic. Transaction-control statements remain blocked.
- Production Horizon dashboard access requires deliberate trusted-operator gate configuration.
